# Implementation Plan

[Overview]

Extend the blocked-route recovery study so the simulated robot discovers and routes around the injected blocker from its **own sensors** instead of being told the vehicle positions, and seal the results as a new package `derived/recovery-sensed-v1/`.

The current recovery-v1 study (sealed) plans every recovery behavior from truth vehicle positions — `recovery.make_entry` even records `"detection": "truth"`. The project's stated follow-up ("sensed blocker detection") is to measure recovery when the planner only sees what the forward range ring (`sensors_vehicle.VehicleMap`) has confirmed: an assumed-size near face, unknown on lap 1. Scope is computer-only and synthetic: no pinned/sealed source file is edited — the entire seam lives in **new files** that subclass the sealed layers (`RecoveryMissionSim`, `AvoidingMissionSim`), exactly as `recovery_sim.py` layered on `mission_avoid.py`. Measurement instrumentation (who the blocker is, whether it contacted, whether it was passed) keeps using ground truth; only the *planning input* is deprived. Results are recorded as measured — never tuned to a preferred direction — matching the repo's negative-result discipline. Dr-registry integration with a `detection:"sensed"` schema is deferred to the DR-lookup follow-up; this package seals its own `rows.json`.

[Types]

No new language-level types; define the following data shapes in `software/stockcar/recovery_sensed.py` (and validate them in the verifier):

- **`SensedVehicle`** — unchanged input shape from `sensors_vehicle.VehicleMap.vehicles()`: `{cx, cy, yaw: 0.0, side: "low"|"high", hits, seen_extent_in, assumed_depth_in}`. Only the near face is measured; `yaw` and the hidden depth are labeled priors (QA03/QA08 open). Reused, not redefined.

- **Row** (`rows.json`, one per run, 1,280 total): `{schema: "recovery-sensed-v1", entry_id: "RS-sim-<scenario>-<behavior>-<pose_mode>-<seed>", world: "world-ccw-line-sq-adv-align", detection: "sensed", scenario, behavior, pose_mode, seed, outcome, completion: bool, contact_free: bool, blocker_passed: bool, blocker_pass_time_s: float|null, blocker_contact_frames: int, time_s: float, replan_count: int, confirm_status: "never"|"before_contact"|"after_contact", source: "sim:evaluate-recovery-sensed-v1"}`.

- **Cell** (`report.json`, 64 total): `{scenario, behavior, pose_mode, runs: 20, completed, passed_blocker, recovered, recovered_contact, blocked, stopped, incomplete, passed_wilson95: [lo, hi], mean_time_s, confirmed_rate, mean_replans, contact_before_confirm}` (integer counts 0–20; `recovered + recovered_contact + blocked + stopped + incomplete === 20`; `passed_blocker === recovered + recovered_contact`).

- **Baseline** (`report.json`): unblocked sensed `stall_stop` runs, 2 pose modes × 20 seeds = 40 rows `{pose_mode, seed, completed, planned_contact_vehicles, lane_modes}`.

- **Comparison** (`report.json`): per-scenario `{oracle_recovered_rate, sensed_recovered_rate}` read from the sealed `derived/recovery-v1/report.json` (read-only) and the sensed cells — no significance test, just the honest side-by-side.

[Functions]

New functions in `software/stockcar/recovery_sensed.py`:

- `confirm_status_of(info) -> "never"|"before_contact"|"after_contact"` — from `info["first_confirm_time_s"]` and the first blocker-contact time; `"never"` when no vehicle cluster ever reached `min_hits`.
- `make_entry_sensed(scenario, behavior, pose_mode, seed, info) -> dict` — the `Row` above (`detection:"sensed"`), keyed to the blocker using the same truth instrumentation fields `recovery.make_entry` uses.
- `run_recovery_sensed(seed, scenario=None, behavior="stall_stop", pose_mode="true_pose", max_steps=4000, replan_lookahead_in=30.0, sense_every=1) -> dict` — mirrors `recovery_sim.run_recovery`; builds a `SensedRecoveryMissionSim`, injects the blocker via `recovery_sim.inject_blocker` (truth), drives to completion, returns the info dict.

New functions in `tools/evaluate-recovery-sensed-v1.py`:

- `main()` — replicates `evaluate-recovery-v1.main()` structure with sensed semantics: `POSE_MODES = {"true_pose": False, "ekf_pose": True}` mapped to the sim's `pose_mode`; loops `SCENARIOS × BEHAVIORS × pose × SEEDS (100–119)`; also runs the 40 unblocked sensed baselines; builds `cells`, `rows`, `baseline`, `comparison`, `summary.md`; writes the manifest with input hashes (the new files plus the same pinned `software/stockcar/*.py` set and `derived/organizer-cad-v10/field-v10.json`) and output hashes.
- `--smoke` flag: restrict to 2 seeds per cell for a fast pre-seal smoke run; the sealed run always uses all 20.

New functions in `tools/verify-recovery-sensed-v1.js`:

- Procedural verifier mirroring `tools/verify-recovery-v1.js`: assert every `manifest.input_hashes` and `manifest.output_hashes` value matches `sha256(readFileSync(...))`; assert `report.seeds` is `[100..119]`; assert exactly 64 cells with valid counts, valid Wilson intervals, and `confirmed_rate`/`mean_replans`/`contact_before_confirm` finite and in `[0, 20]`; assert `rows.json` has exactly 1,280 entries, each `detection === "sensed"`, entry-id pattern, `confirm_status` in the enum, `replan_count >= 0`; assert the baseline has 40 rows; assert the comparison table has one row per scenario. No assertion on favorable values.

Modified functions: none (sealed layers reused by import and subclassing). Removed functions: none.

[Classes]

New class `SensedRecoveryMissionSim(RecoveryMissionSim)` in `software/stockcar/recovery_sensed.py`:

- `__init__(self, behavior="stall_stop", pose_mode="true_pose", replan_lookahead_in=30.0, sense_every=1, **kwargs)` — validates `behavior` against `recovery.BEHAVIORS + (recovery.AUTO,)`; calls `super().__init__(behavior, sensing=(pose_mode == "ekf_pose"), **kwargs)` (the parent `sensing` flag selects EKF pose estimation; vehicle sensing is *always* on in this class); stores the parameters; initializes `self.vmap = VehicleMap()`, `self.scan_rng = random.Random(0)`, `self.replanned_vehicle_count = 0`, `self.replan_count = 0`, `self.first_confirm_time_s = None`.
- `build_routes(self, layout)` — **override**: always build the discovery lap on plain lanes (`self._set_lap_route([], [])` plus `self._build_pit_routes(layout)`), regardless of behavior. The parent's truth and `v10_blend` paths are bypassed so no vehicle position leaks into the first plan.
- `_sense(self)` — call `self.vmap.add(scan(self.pose, self.barriers, self.layout.polys, self.scan_rng), self.pose)` every `sense_every` steps; record the first time any cluster reaches `VehicleMap.min_hits` into `first_confirm_time_s`.
- `_replan_from_sensed(self)` — gather `vehs = self.vmap.vehicles()`; for each straightaway side build the behavior's plan from **sensed** vehicles only:
    - `lateral_shift` / `auto`: `y = recovery.widest_open_band(self.field, side, vehs)`; if `y is not None` use the fixed span `[(x0, x1, y)]`; else `auto` falls back to threading via `self._spans(side, polys)` and `lateral_shift` fails honestly to the naive lane (replicating `recovery.decide_recovery`).
    - `replan_lanes`: `self._spans(side, [obstacle_footprint(GUIDE_PLUSH, v["cx"], v["cy"], v["yaw"]) for v in side vehicles])` — the same assumed-size near-face prior `mission_avoid._replan` uses.
    - `stall_stop`: never replans (stay on plain lanes → drive in → stall watchdog; the no-recovery baseline).
  Then `self._set_lap_route(low_spans, high_spans)`.
- `step(self, action=None)` — **override**: run `_sense()` every `sense_every` steps; after `super().step(action)`, if the sensed vehicle count grew **and** any newly sensed vehicle on the current route side sits within `replan_lookahead_in` ahead in travel direction (low: `x - self.state["x"]` in `(0, 30]`; high: `self.state["x"] - x` in `(0, 30]`), call `_replan_from_sensed()` and increment `replan_count`. Mid-lap rebuilds use the same fixed anchors as `RecoveryMissionSim.build_routes`, so the tracker stays consistent.
- `info(self)` — extend the parent info with `{replan_count, sensed_vehicles: len(self.vmap.vehicles()), first_confirm_time_s}`.

Inherited unchanged (truth instrumentation only): `_blocker_contact`, `_update_blocker`, `classical_action`, `reset` (re-initializes `vmap`/`scan_rng`/counters after clearing parent state), `blocker_poly`, and the outcome fields `recovery.outcome_of` reads.

[Testing]

- `software/stockcar/tests/test_recovery_sensed.py` (unittest, stdlib, fast) — six tests:
    1. `test_first_plan_has_no_vehicle_knowledge` — reset a sim with an injected blocker; assert `lane_modes` are `"clear"`, `infeasible_vehicles == 0`, and no truth vehicle influenced the route (guards the deprivation).
    2. `test_scan_confirms_a_blocker_ahead` — pose the robot on the low side at x=52 (before the low_mid blocker at cx=60), step several times; assert `vmap.vehicles()` gains a low-side cluster and `first_confirm_time_s` is set.
    3. `test_replan_fires_on_lookahead` — continue stepping; assert `replan_count >= 1` and `lane_modes` leaves `"clear"` for an `auto`/`replan_lanes` run once the blocker is confirmed within lookahead.
    4. `test_sensed_lane_matches_near_face_prior` — with `behavior="replan_lanes"`, after the trigger, assert the rebuilt LAP lane equals the `_spans` computed manually from `vmap.vehicles()` (assumed-size, yaw=0), not from `layout.vehicles` truth.
    5. `test_stall_stop_never_replans` — `stall_stop` keeps `"clear"` lanes to contact/stall; `replan_count == 0`.
    6. `test_entry_and_confirm_status` — feed synthetic info dicts and assert `make_entry_sensed` shape (`detection:"sensed"`, entry-id) and `confirm_status_of` returns `before_contact`/`after_contact`/`never` correctly.
- `tests/recovery-sensed-v1.test.js` — Node wrapper: `spawnSync(node, [tools/verify-recovery-sensed-v1.js])` exits 0; parse `report.json` for 64 cells and `rows.json` for 1,280 rows.
- `tools/verify-recovery-sensed-v1.js` — structural + hash verifier (see Functions); added to `check-all` (44 verifiers, 48 steps).
- Existing suites must keep passing byte-identically: `tests/recovery-v1.test.js`, `tools/verify-recovery-v1.js` (the v1 seal proves no pinned file was touched), `tests/ai-orchestration-tasks.test.js`, `tests/inspect-tire-stl.test.js`, `tests/folder-breakdown.test.js`, `software/stockcar/tests/test_build_field_tables.py`.
